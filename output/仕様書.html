1 概要

1.1 概要

本書は在庫管理システム(以下、本システム)のソフトウェア仕様を定めるものである。

注: 見出しに章番号は記載しない。番号は wiki.js / MkDocs 上では CSS カウンタ、PDF では Pandoc の --number-sections により自動採番される。

1.1.1 目的

本システムは、倉庫内の在庫情報をリアルタイムに管理し、入出庫作業の効率化と棚卸工数の削減を目的とする。

1.1.2 対象読者

本書は以下の読者を対象とする。

  • 開発担当者(実装・テストの根拠として参照)
  • 保守担当者(改修時の影響範囲調査に使用)
  • 顧客側システム担当者(受入検収の基準として参照)

1.1.3 用語定義

用語 説明
SKU Stock Keeping Unit。在庫管理上の最小識別単位
ロケーション 倉庫内の棚位置を示すコード
引当 出荷指示に対して在庫を確保する処理

1.1.4 機能一覧

本システムが提供する機能の一覧を示す。画面仕様・API仕様の各章は本一覧の機能IDに対応する。

機能ID 機能名 概要
F-001 ログイン 利用者認証を行う
F-002 在庫照会 SKU・ロケーション単位で在庫を検索する
F-003 入庫登録 入庫実績を登録し在庫数を加算する
F-004 出庫登録 出庫実績を登録し在庫数を減算する

1.1.5 関連文書

  • 要件定義書(REQ-2026-001)
  • 画面設計書(UI-2026-002)

2 システム構成

2.1 システム構成

2.1.1 全体構成

本システムは Web アプリケーションとして構築し、クライアント・API サーバ・データベースの 3 層構成とする。

[ブラウザ] --HTTPS--> [APIサーバ (Node.js)] ---> [PostgreSQL]
                              |
                              +--> [Redis (セッション/キャッシュ)]

2.1.2 技術スタック

層 技術 バージョン
フロントエンド Vue.js 3.x
バックエンド Node.js / Express 20.x / 4.x
データベース PostgreSQL 16.x
キャッシュ Redis 7.x

2.1.3 コンポーネント構成

2.1.3.1 API サーバ

REST API を提供する。認証・在庫・入出庫・マスタ管理の 4 モジュールで構成する。

2.1.3.2 バッチ処理

夜間バッチとして以下を実行する。

  1. 在庫スナップショットの作成(毎日 2:00)
  2. 操作ログのアーカイブ(毎週日曜 3:00)

2.1.3.3 外部連携

基幹システムとは CSV ファイルの SFTP 連携とする。連携仕様は外部インタフェース仕様の章を参照。

3 画面仕様

3.1 ログイン画面 (F-001)

ユーザ ID とパスワードを入力し認証する。5 回連続で失敗した場合、アカウントを 30 分間ロックする。

3.1.1 画面仕様

項目 型 必須 説明
ユーザID テキスト ○ 半角英数 8 桁
パスワード パスワード ○ 12 文字以上
ログインボタン ボタン - 入力値を送信し認証を行う

3.1.2 処理フロー

  1. 入力値のバリデーション(ID: 半角英数 8 桁、パスワード: 12 文字以上)
  2. パスワードハッシュ(bcrypt)の照合
  3. セッショントークンの発行(有効期限 8 時間)

3.1.3 エラー仕様

コード メッセージ 条件
E-0101 IDまたはパスワードが不正です 認証失敗
E-0102 アカウントがロックされています ロック中

3.2 在庫照会画面 (F-002)

SKU・ロケーション単位で在庫を検索し、一覧表示する。検索結果は在庫照会 API を通じて取得する。

3.2.1 検索条件

SKU コード(前方一致)、ロケーション(完全一致)、在庫区分(良品/不良品)を指定できる。

項目 型 必須 説明
SKUコード テキスト - 前方一致で検索
ロケーション テキスト - 完全一致で検索
在庫区分 プルダウン - 良品 / 不良品

3.2.2 検索結果一覧

列 説明
SKU 在庫の最小識別単位
ロケーション 棚位置コード
数量 現在在庫数
在庫区分 良品 / 不良品

検索結果が 0 件の場合は「該当する在庫がありません」を表示する。

3.3 入庫登録画面 (F-003)

入庫実績を登録し、対象 SKU・ロケーションの在庫数を加算する。

3.3.1 画面仕様

項目 型 必須 説明
SKUコード テキスト ○ 入庫対象の SKU
ロケーション テキスト ○ 格納先の棚位置
入庫数量 数値 ○ 1 以上の整数
登録ボタン ボタン - 入庫実績を確定する

3.3.2 処理フロー

  1. 入力値のバリデーション(数量は 1 以上の整数)
  2. 対象 SKU・ロケーションの在庫数に入庫数量を加算
  3. 入庫履歴の記録(登録者・登録日時)

3.3.3 エラー仕様

コード メッセージ 条件
E-0301 入庫数量は 1 以上で入力してください 数量が 0 以下
E-0302 該当する SKU が存在しません 未登録の SKU

3.4 出庫登録画面 (F-004)

出庫実績を登録し、対象 SKU・ロケーションの在庫数を減算する。

3.4.1 画面仕様

項目 型 必須 説明
SKUコード テキスト ○ 出庫対象の SKU
ロケーション テキスト ○ 出庫元の棚位置
出庫数量 数値 ○ 1 以上の整数
登録ボタン ボタン - 出庫実績を確定する

3.4.2 処理フロー

  1. 入力値のバリデーション(数量は 1 以上の整数)
  2. 引当済み在庫数の確認(出庫可能数を超えないこと)
  3. 対象 SKU・ロケーションの在庫数から出庫数量を減算
  4. 出庫履歴の記録(登録者・登録日時)

3.4.3 エラー仕様

コード メッセージ 条件
E-0401 出庫数量が在庫数を超えています 在庫不足
E-0402 出庫数量は 1 以上で入力してください 数量が 0 以下

4 API仕様

4.1 在庫照会API (F-002)

在庫照会画面から呼び出す、在庫検索用の REST API。

4.1.1 リクエスト

GET /api/v1/stocks?sku=A100&location=B-01-02
Authorization: Bearer {token}
クエリパラメータ 必須 説明
sku - SKU コード(前方一致)
location - ロケーション(完全一致)
status - 在庫区分(good / defective)

4.1.2 レスポンス

{
  "items": [
    { "sku": "A1001234", "location": "B-01-02", "qty": 120, "status": "good" }
  ],
  "total": 1
}

4.1.3 エラーレスポンス

HTTP コード 条件
401 E-0102 トークン不正・期限切れ
400 E-0201 クエリパラメータの形式不正

4.2 入庫登録API (F-003)

入庫登録画面から呼び出す、入庫実績登録用の REST API。

4.2.1 リクエスト

POST /api/v1/receipts
Authorization: Bearer {token}
Content-Type: application/json

{
  "sku": "A1001234",
  "location": "B-01-02",
  "qty": 50
}
ボディ項目 必須 説明
sku ○ 入庫対象の SKU
location ○ 格納先のロケーション
qty ○ 入庫数量(1 以上の整数)

4.2.2 レスポンス

{
  "receiptId": "R-20260730-0001",
  "sku": "A1001234",
  "location": "B-01-02",
  "qty": 50,
  "stockAfter": 170
}

4.2.3 エラーレスポンス

HTTP コード 条件
401 E-0102 トークン不正・期限切れ
400 E-0301 入庫数量が 1 未満
404 E-0302 該当する SKU が存在しない
